SCENARIO s15_deadlock
Title : Deadlock — two staff update the same two materials in opposite order
Level : READ COMMITTED
Expect: A holds poplin and waits for buttons; B holds buttons and waits for poplin. PostgreSQL detects the cycle (after deadlock_timeout, 1 s), aborts B with SQLSTATE 40P01, and A carries on.


   time     # S  statement  →  result
  0.00s  [ 1] A  BEGIN;  →  BEGIN
  0.15s  [ 2] A  UPDATE material SET stock_qty = stock_qty - 1 WHERE material_id = 1;  →  UPDATE 1
  0.31s  [ 3] B  BEGIN;  →  BEGIN
  0.46s  [ 4] B  UPDATE material SET stock_qty = stock_qty - 1 WHERE material_id = 7;  →  UPDATE 1
  0.62s  [ 5] A  UPDATE material SET stock_qty = stock_qty - 1 WHERE material_id = 7;  →  ⏳ BLOCKED (waiting for a lock)
  3.07s  [ 6] B  UPDATE material SET stock_qty = stock_qty - 1 WHERE material_id = 1;  →  ERROR [40P01] deadlock detected
  4.22s  [ 5] A  ↳ UNBLOCKED after 3.60s → UPDATE 1
  4.22s  [ 7] B  ROLLBACK;  →  ROLLBACK
  4.37s  [ 8] A  COMMIT;  →  COMMIT
